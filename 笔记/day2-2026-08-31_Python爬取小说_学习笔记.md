# Python 爬取小说｜学习笔记

## 0. 本节课的主线

今天的代码完成了“请求网页 → 解析 HTML → 提取正文 → 清洗 → 保存 → 翻到下一章 → 判断结束”的完整链路。

~~~text
URL
↓
requests.get()
↓
Response 响应对象
↓ response.text
HTML 字符串
↓ etree.HTML()
HTML 文档对象
↓ e.xpath()
标题、正文和下一章链接
↓
清洗并保存
↓
break 或更新下一章 URL
~~~

## 1. 请求、响应和网页正文

~~~python
import requests

response = requests.get(url)
~~~

requests.get(url) 返回的是 Response 响应对象，不是网页字符串。

可以把 response 理解为一个装着服务器返回信息的对象：

~~~text
response
├── status_code   HTTP 状态码
├── headers       响应头
├── url           最终请求地址
├── content       原始字节数据
└── text          解码后的网页正文
~~~

response.text 表示从 Response 对象中取出网页正文，并将它解码成 Python 的 str 字符串。

这里不是“把请求转换成文本”：

- request 是发给服务器的请求；
- response 是服务器返回的响应；
- response.text 是响应中的网页正文。

~~~python
response = requests.get(url)  # Response 对象
html_text = response.text     # str 字符串
~~~

response.text 是对象属性，不是独立函数，因此写成 response.text，而不是 text(response)。

## 2. etree.HTML 和 xpath

导入：

~~~python
from lxml import etree
~~~

解析：

~~~python
e = etree.HTML(response.text)
~~~

执行过程：

~~~text
response.text
↓
HTML 字符串
↓ etree.HTML()
HTML 文档对象
↓
赋值给变量 e
~~~

etree.HTML() 是 lxml.etree 模块中的函数，负责把 HTML 字符串解析成树状文档对象。

解析前，response.text 只是普通字符串，不能直接调用 XPath：

~~~python
response.text.xpath(...)  # 不可以
~~~

解析后，e 是 HTML 文档对象，可以调用它的 xpath 方法：

~~~python
e.xpath(...)
~~~

这里的 e.xpath 表示“调用 e 对象提供的 xpath 方法”。

## 3. XPath 提取数据

### 3.1 提取正文

~~~python
paragraphs = e.xpath(
    "//article[@class='article-post']/p/text()"
)
~~~

XPath 拆解：

~~~text
//article                  查找 article 标签
[@class='article-post']    筛选 class 属性
/p                         查找其下面的 p 标签
/text()                    提取 p 标签中的文字
~~~

返回结果通常是段落字符串列表：

~~~python
[
    "第一段内容",
    "第二段内容",
    "第三段内容",
]
~~~

所以：

~~~text
paragraphs → list
列表中的每个元素 → str
~~~

### 3.2 提取标题

~~~python
title = e.xpath("//title/text()")[0]
~~~

xpath 查询通常先返回列表，例如：

~~~python
["斗罗大陆 - 第一章"]
~~~

然后 [0] 取出列表中的第一个字符串。

如果没有匹配结果，直接使用 [0] 会产生 IndexError。调试时可以先写：

~~~python
titles = e.xpath("//title/text()")
print(titles)
~~~

### 3.3 提取下一章链接

网页中的 href 可能返回相对路径：

~~~text
/wl/douluodaliu/216993.html
~~~

它不是完整 URL。

最小拼接方式：

~~~python
next_path = e.xpath(
    "//div[@class='col-md-12 col-lg-10']/p[1]/a/@href"
)[0]

url = "https://www.wyshu.com" + next_path
~~~

更通用的方式：

~~~python
from urllib.parse import urljoin

next_path = e.xpath(
    "//div[@class='col-md-12 col-lg-10']/p[1]/a/@href"
)[0]

url = urljoin(response.url, next_path)
~~~

建议区分变量含义：

~~~text
next_path → XPath 找到的下一章相对路径
url       → 下一轮 requests 使用的完整 URL
~~~

## 4. MissingSchema 的根因

最开始的 url 是完整网址：

~~~python
url = "https://www.wyshu.com/wl/douluodaliu/216992.html"
~~~

错误写法是把 XPath 返回的相对路径直接赋值给 url：

~~~python
url = e.xpath(...)[0]
~~~

第一轮循环可能正常：

~~~text
url = https://www.wyshu.com/...
↓
requests.get(url) 请求成功
↓
XPath 找到下一章
↓
url 被改成 /wl/douluodaliu/216993.html
~~~

第二轮实际执行：

~~~python
requests.get("/wl/douluodaliu/216993.html")
~~~

这个地址没有 http:// 或 https://，所以出现：

~~~text
requests.exceptions.MissingSchema
Invalid URL
No scheme supplied
~~~

根因不是 XPath 不能提取链接，而是提取到的相对路径必须先补全，再交给 requests.get()。

## 5. while 循环中的 URL 变化

~~~python
url = "第一章完整网址"

while True:
    response = requests.get(url)
    ...
    url = "下一章完整网址"
~~~

循环外的初始化代码只执行一次。

执行过程：

~~~text
初始化 url = 第一章
↓
第1轮请求第一章
↓
找到下一章并更新 url
↓
第2轮请求第二章
↓
找到下一章并更新 url
~~~

下一轮使用的是上一轮修改后的 url，不会重新执行最开始的 URL 赋值。

## 6. break 为什么能结束 while

~~~python
while True:
    for i in info:
        ...

    if "本书完" in response.text:
        break
~~~

break 只结束包含它的最近一层循环。

这里 if 不是循环，而且 if 与 for 是同级缩进，说明 break 已经不在 for 内部，因此它结束的是外层 while。

如果 break 写在 for 内部：

~~~python
while True:
    for i in info:
        if condition:
            break
~~~

它只结束 for，while 仍然继续。

同级的其他循环也不会被 break 结束。

## 7. 文件保存：w 和 a

### 7.1 w 为什么只能留下最后一章

如果循环中使用：

~~~python
with open("斗罗大陆.txt", "w", encoding="utf-8") as f:
    f.write(...)
~~~

w 是覆盖写入模式，每次打开文件都会清空旧内容：

~~~text
第1轮：写入第1章
第2轮：清空文件，再写第2章
第3轮：清空文件，再写第3章
~~~

因此最后只剩最后一章。

### 7.2 正确的追加方式

循环外清空一次：

~~~python
with open("斗罗大陆.txt", "w", encoding="utf-8") as f:
    pass
~~~

循环内追加：

~~~python
with open("斗罗大陆.txt", "a", encoding="utf-8") as f:
    f.write(title + "\n\n" + info + "\n\n")
~~~

a 是追加模式，会保留旧内容并把新章节写到文件末尾。

## 8. 最后一章如何停止

最后一页显示“本书完”。正确顺序是：

~~~text
请求当前章节
↓
提取正文和标题
↓
保存当前章节
↓
判断是否出现“本书完”
↓
是：break
↓
否：获取下一章 URL
↓
进入下一轮
~~~

推荐写法：

~~~python
with open("斗罗大陆.txt", "a", encoding="utf-8") as f:
    f.write(title + "\n\n" + info + "\n\n")

if "本书完" in response.text:
    print("小说已经结束")
    break

next_path = e.xpath(
    "//div[@class='col-md-12 col-lg-10']/p[1]/a/@href"
)[0]

url = urljoin(response.url, next_path)
~~~

必须先保存，再判断结束，否则最后一章可能不会写入文件。

原代码中的：

~~~python
last_url = e.xpath(
    "//div[@class='col-md-12 col-lg-10']/p[2]/a/@href"
)[0]
~~~

根据页面按钮顺序，p[2] 对应“上一章”链接，不是“最后一章 URL”，不能用它判断小说结束。

如果最后一页的“下一章”链接仍然指向当前页面，还可以比较 URL：

~~~python
next_url = urljoin(response.url, next_path)

if next_url == response.url:
    print("下一章链接与当前页面相同，程序结束")
    break

url = next_url
~~~

## 9. \xa0 的来源和清洗

实际字符是 \xa0，最后一位是数字 0，不是字母 o。

它通常来自网页源码中的：

~~~html
&nbsp;
~~~

&nbsp; 表示不换行空格。经过 lxml 解析后，可能变成 Python 中的 Unicode 字符 \xa0。

它不是程序错误，而是合法的空白字符。

### 9.1 为什么有时看得见，有时看不见

打印列表时，Python 可能把特殊空格显示为转义形式：

~~~python
print(info)
~~~

可能显示：

~~~python
["第一段内容\xa0第二段内容"]
~~~

直接打印字符串时，\xa0 通常只显示成普通空白，肉眼看不出区别。

使用 repr() 查看真实内容：

~~~python
print(repr(info))
print("\xa0" in info)
~~~

如果 info 是列表：

~~~python
print(any("\xa0" in item for item in info))
~~~

### 9.2 原来的清洗代码

原来的 info 是段落列表：

~~~python
info = e.xpath(
    "//article[@class='article-post']/p/text()"
)

l = []

for i in info:
    l.append(i.replace("\xa0", " ").strip())
    x = "\n".join(l)
~~~

对象关系：

~~~text
info → 原始段落列表
i    → 当前段落字符串
l    → 清洗后的段落列表
x    → 拼接后的最终字符串
~~~

如果保存 x，清洗后的内容才会被写入文件：

~~~python
f.write(title + "\n\n" + x + "\n\n")
~~~

### 9.3 当前版本为什么仍能运行

当前代码先执行：

~~~python
info = "\n".join(e.xpath(...))
~~~

此时 info 已经是一个字符串。

清洗代码被注释后不会执行，但 info 已经生成，保存时又直接使用 info，所以程序仍能请求、解析和保存。

如果把原来的 for i in info 取消注释，当前版本会逐字符遍历字符串，而不是逐段遍历列表。

推荐清洗写法：

~~~python
paragraphs = e.xpath(
    "//article[@class='article-post']/p/text()"
)

info = "\n".join(
    paragraph.replace("\xa0", " ").strip()
    for paragraph in paragraphs
)
~~~

如果只想替换特殊空格：

~~~python
info = info.replace("\xa0", " ")
~~~

### 9.4 不清洗的影响

通常不会影响：

~~~text
requests.get()
etree.HTML()
e.xpath()
while
break
文件保存
~~~

主要影响数据质量：

- 精确字符串比较可能失败；
- 关键词匹配可能出现意外结果；
- split(" ") 不一定能按特殊空格分割；
- 去重时可能把视觉相同的文本当成不同值；
- 导出的文本中可能出现不明显的特殊空白。

## 10. 当前代码推荐版本

~~~python
from urllib.parse import urljoin

import requests
from lxml import etree


url = "https://www.wyshu.com/wl/douluodaliu/216992.html"

# 每次重新运行时先清空旧文件一次
with open("斗罗大陆.txt", "w", encoding="utf-8") as f:
    pass

while True:
    headers = {
        "User-Agent": (
            "Mozilla/5.0 (Windows NT 10.0; Win64; x64) "
            "AppleWebKit/537.36 (KHTML, like Gecko) "
            "Chrome/152.0.0.0 Safari/537.36 Edg/152.0.0.0"
        )
    }

    response = requests.get(url, headers=headers)
    response.encoding = "utf-8"
    e = etree.HTML(response.text)

    paragraphs = e.xpath(
        "//article[@class='article-post']/p/text()"
    )
    info = "\n".join(
        paragraph.replace("\xa0", " ").strip()
        for paragraph in paragraphs
    )
    title = e.xpath("//title/text()")[0]

    with open("斗罗大陆.txt", "a", encoding="utf-8") as f:
        f.write(title + "\n\n" + info + "\n\n")

    print(title)

    if "本书完" in response.text:
        print("小说已经结束")
        break

    next_path = e.xpath(
        "//div[@class='col-md-12 col-lg-10']/p[1]/a/@href"
    )[0]
    url = urljoin(response.url, next_path)
~~~

这份版本的关键点：

1. url 始终保持完整 URL。
2. response.text 是网页字符串。
3. etree.HTML() 把字符串解析成 HTML 文档对象。
4. xpath() 返回列表，需要取值或遍历。
5. info 在保存前完成清洗。
6. 文件循环外用 w 清空一次，循环内用 a 追加。
7. 保存当前章节后，再判断是否为最后一章。
8. 只有不是最后一章时，才更新下一章 URL。

## 11. 今天遇到的两个错误

### 11.1 SSLError: UNEXPECTED_EOF_WHILE_READING

第一次请求时出现 HTTPS 连接异常，网页尚未成功返回，不能优先去修改 XPath 或编码。

之后同一网址成功返回 200，且没有重定向。因此当时更符合临时网络或服务器连接异常，不是爬虫逻辑的根因。

### 11.2 MissingSchema

这是代码逻辑问题：把 XPath 返回的相对路径直接赋给 url，导致下一轮请求缺少协议和域名。

排查顺序应是：

~~~text
请求是否成功
↓
response.text 是否拿到 HTML
↓
etree.HTML() 是否解析
↓
XPath 是否选中
↓
数据是否清洗
↓
文件是否正确保存
~~~

## 13. 核心模型

~~~text
输入：URL
↓
请求：requests.get()
↓
响应：Response
↓
正文：response.text / str
↓
解析：etree.HTML()
↓

↓

↓
输出：文本文件
↓
~~~
